# Design

## Context

See proposal.md. Red is generated by the sim from the map seed with `RedSkills` skills. The server computes `RedSkills` per battle and stores it, and the client builds its input from what the server issued.

## Goals / Non-Goals

**Goals:** longer runs with a gentle difficulty curve, set by the server and verifiable like everything else.

**Non-Goals:** counter-picking, changing veterans.

## Decisions

**Health, not unit count.**
- The lab tried three levers:
  - **Fewer Red units early:** 5 against 4 or 3 made matches 1–2 about 100% wins (free wins).
  - **Counter-picking:** made runs shorter.
  - **Scaling Red's health:** 85/90/95% gives 88/82/72% wins, then the normal ~64%. A smooth curve, chosen with the user.
- The health scaling applies to Red's maximum health at spawn (`MaxHP` and `HP`), after skills (Toughness included). Executioner and Headshot's "below 40%" threshold therefore uses the reduced maximum, consistently.

**The input field defaults to full health.**
- `RedHealthPct` 0 means 100 (proto3 default), and validation allows 0–100.
- Inputs without the field play exactly as before, so no version bump is needed. The golden replays are unchanged, and one new golden case covers 85%.

**The server is the authority.**
- `run.RedHealthFor(match)` holds the curve (85, 90, 95, then 0).
- `StartBattle` stores it in `battles.red_health_pct` (migration 0003, default 0) and returns it. `VerifyBattle` rebuilds the input from the stored value.
- If the curve changes later, battles already issued still verify with the value they were issued with.

**How determinism is preserved and tested.**
- A sim test checks that Red units start at exactly 85% of their skilled maximum, and that validation rejects values outside 0–100.
- The golden replays (all of them unchanged, plus the new 85% case) run natively and under WASM.
- A server test checks that match 1 is issued 85% and match 4 gets 0, and that verification uses the stored value: a claim played at 100% for a match-1 battle is not fair.

## Risks / Trade-offs

- [The tuning assumes a "best picks" player with a balanced army] → Other policies in the lab land close (see the report). The curve is one table, `run.RedHealthFor`, easy to retune.
- [It's a quiet buff players can't see] → The run bar shows Red's strength while the ramp applies.
